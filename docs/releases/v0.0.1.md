# v0.0.1

> **Low-Light Image Enhancement** · 初始版本 · 2026-08-09 🎉

这是 `lowlight-image-enhance` 的第一个发布版本，目标是**把框架搭起来、把流程跑通**：从一张低光照 BGR 图像出发，经过「前置降噪 → LCH 色彩空间 → 亮度增益 → 饱和度补偿」，输出一张增强图，并提供一个可用的 CLI 入口。

## 🚀 亮点

- **亮度增益驱动饱和度补偿**：在 LCH 色彩空间中解耦 Lightness / Chroma / Hue，用亮度增益量 ΔL 直接驱动饱和度补偿，避免单纯提亮后图像"发灰"
- **端到端可运行**：`pip install -e .` + 一行 CLI 即可出图，`examples/` 提供了样例输入与输出
- **完整的工程骨架**：src 布局、`pyproject.toml`、CLI 入口、单元测试、文档、MIT License

## ✨ 新增功能

### 处理流程（`pipeline.enhance()`）

1. `imread` → 读取低光 BGR 图
2. `denoiser` → 前置降噪（`denoiser.non_local_means_color`，直接处理 BGR uint8）
3. `BGR2LCH` → 转到 LCH 色彩空间
4. `L_boost` → 亮度增益（`lightness.boost`，当前用 gamma 占位，默认 0.5），产出 ΔL
5. `C_compensate` → 由 ΔL 驱动饱和度补偿（`chroma.compensate`），产出 ΔC
6. `LCH2BGR` → 转回 BGR 并保存

### 模块

- **色彩空间**（`colorspace.py`）：`BGR ↔ LAB ↔ LCH` 全套转换，统一 L[0,1] / C[0,1] / H[-π,π] 的数值范围，让后续增益/补偿的数学运算更直观
- **降噪**（`denoiser.py`）：高斯模糊、双边滤波、NLM（单通道 + 彩色）
- **评估指标**（`metrics.py`）：PSNR、SSIM（手写实现，与 `skimage` 结果差距在小数点后第三位）
- **工具**（`utils.py`）：`imread` / `imwrite` / `normalize` / `denormalize`
- **命令行**（`cli.py`）：`lowlight-enhance` 入口，支持 `--output_dir`，带异常捕获、日志输出与非零退出码
- **日志**：全库用 `logging` 取代 `print` —— 库内只发日志、CLI 入口统一配置，被他人 `import` 使用时保持安静

## 🧪 测试

4 个测试全部通过：

- **色彩转换往返**：BGR u8 → f32 → LAB → LCH → LAB → BGR → u8 全链路 dtype 与数值范围检查 + 往返误差上限断言
- **误差来源分层**：把转换链按 3 层（u8↔f32、BGR↔LAB、LAB↔LCH）分别测往返误差，定位误差主要来自 `cv2.cvtColor`（f32↔LAB 最大误差 ~0.0037，导致 uint8 一个像素级的误差）
- **读写往返**：`imwrite` 后再 `imread` 无损还原
- **异常处理**：读取不存在的文件抛出 `FileNotFoundError`

## ⚠️ 目前局限

### 简单算法占位
> 这一版用简单算法搭起框架并跑通，核心算法留待后续迭代。
- **亮度增益**：目前用 `gamma` (γ=0.5) 占位，其它算法待补充
- **饱和度补偿**：目前用线性公式 `ΔC = k·ΔL`（k=0.3）占位

### 已关注的问题
1. colorspace 在 BGR 和 LCH 之间的往返误差稍大，不能做到无损转换（在 uint8 下最大误差为 1），测试发现主要误差来源是 cv2.cvtColor 的 BGR <-> LAB 的转换过程。
2. 增强后的图像出现**色带**，具体原因还不清楚，推测是补偿算法导致的饱和度分层。这个现象也许会在后续换用更好的补偿算法后消失。
3. lightness.boost() 和 chroma.compensate() 的算法参数尚未透传，CLI 目前无法指定

## 🔭 下一步
- **亮度增益算法**：添加 HE / CLAHE / Retinex 三种算法
- **饱和度补偿算法**：定位条带问题，用更扎实的 ΔL 驱动补偿算法替换线性占位
- **参数透传**：完善 pipeline 可选参数透传
